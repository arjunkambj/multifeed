# MultiFeed codebase audit

Audited on September 5, 2026. Overall rating: **6/10**.

The code has a solid TypeScript foundation, clear domain boundaries, and several thoughtful security controls. The score is held down by defects in the main publishing and editing flows, incomplete billing safeguards, and advertised features that have no implementation. I would fix the publishing and billing findings before treating this as a dependable paid scheduling service.

This is an engineering assessment, not a measured quality percentage. The weighted score is 5.85, rounded to 6/10. A score of 5 means a working prototype with consequential gaps; 8 means a dependable product with limited remaining risks; 10 would require unusually strong correctness, operations, and evidence under real workloads.

**Findings, ordered by practical priority**

1. **P1: Post now never reaches a first publishing attempt.** The composer sends `status: "publishing"`. Creation and update give targets that same status and a fresh `updatedAt`. `scheduleTargets` treats those targets as already running and skips them for 12 minutes. After that, `claimTargetForPublish` sees a publishing target without a checkpoint and marks it `stale_publish`. This affects both a new post and an edited draft sent with Post now. Start targets in a queued state, and let the claim mutation alone transition them to publishing. High confidence from the complete state transition; no external post was submitted. See [composer submission](/Users/honey/Code/Multifeed/apps/web/src/components/posts/CreatePostComposer.tsx:547), [target creation](/Users/honey/Code/Multifeed/apps/backend/convex/posts.ts:546), [scheduler skip](/Users/honey/Code/Multifeed/apps/backend/convex/publishing.ts:65), and [stale handling](/Users/honey/Code/Multifeed/apps/backend/convex/publishing.ts:185).

2. **P1: Any authenticated team member can request the team's billing portal.** The route checks identity and loads the selected team's subscription, then uses the server API key to create a portal session. It never checks a billing-management permission. Checkout has the same missing role check, while the invitation route demonstrates an explicit permission check elsewhere in the app. Add a server-side owner or billing-admin check to both billing routes and reflect it in the UI. The missing check is confirmed; the exact actions exposed by the configured Dodo portal were not exercised. See [portal route](/Users/honey/Code/Multifeed/apps/web/src/app/api/billing/portal/route.ts:30) and [checkout route](/Users/honey/Code/Multifeed/apps/web/src/app/api/billing/checkout/route.ts:35).

3. **P1: A publishing batch can exceed Convex's scheduling limit and roll back.** The cron processes up to 100 posts and directly schedules every eligible target, with up to 100 targets per post. Eleven due posts with 100 eligible targets already require 1,100 scheduled functions. The documented limit is 1,000 per mutation. Schedule a bounded set of per-post dispatcher mutations, or budget total targets and continue in another transaction. The calculated failure condition is clear; it was not load-tested on the hosted deployment. See [batch dispatcher](/Users/honey/Code/Multifeed/apps/backend/convex/publishing.ts:101) and the [official Convex limits](https://docs.convex.dev/production/state/limits#execution-time-and-scheduling).

4. **P1: Multiple checkout sessions can be completed for one team.** Checkout reads the current subscription and then creates an external session without storing or reusing a pending intent. Two requests before the first subscription webhook arrives can both succeed. The check also cannot invalidate an older outstanding checkout link. Use a durable team checkout intent, provider idempotency where supported, and reconciliation for conflicting subscriptions. This is a source-confirmed race window; duplicate purchases were not attempted. See [subscription check and session creation](/Users/honey/Code/Multifeed/apps/web/src/app/api/billing/checkout/route.ts:81).

5. **P2: Media cannot be removed from a saved post through the composer.** Remove calls `deleteMedia` first and only updates the editor after deletion succeeds. The backend correctly rejects deletion whenever any saved post references the asset. Editing or duplicating a saved image/video post therefore cannot remove that attachment through this control. Detach it from the editor and save the relationship change; offer storage deletion separately when no references remain. See [remove handler](/Users/honey/Code/Multifeed/apps/web/src/components/posts/PostMediaUploader.tsx:298) and [reference guard](/Users/honey/Code/Multifeed/apps/backend/convex/media/r2.ts:155).

6. **P2: Repeated Save draft creates duplicate records.** After a first draft save, the composer stays open but does not retain the returned post ID or navigate to edit mode. Subsequent saves still call `createPost`. A later Schedule action creates another record and leaves the previous draft behind. Persist the new ID and switch subsequent submissions to update. See [submission result and draft return](/Users/honey/Code/Multifeed/apps/web/src/components/posts/CreatePostComposer.tsx:563).

7. **P2: Billing product changes can retain the wrong plan limits.** The webhook takes `planKey` and interval from metadata or the existing record, while separately accepting a changed `product_id`. A signed plan-change event containing a new product and unchanged or absent plan metadata updates the billed product but retains the old entitlements. Derive the plan and interval from a trusted product-ID mapping and reject unknown products. The behavior for this event shape is confirmed from code; the live portal's event payload was not inspected. See [subscription mapping](/Users/honey/Code/Multifeed/apps/backend/convex/billing.ts:329).

8. **P2: The post library silently hides older records.** All posts fetches at most 100 rows. Search filters only that returned array, and there is no cursor or Load more control. A draft outside the most recent 100 results for its filter becomes unreachable through this library. The calendar caps results at 500 and returns `truncated`, but its component ignores that flag. Add pagination and visibly disclose any remaining truncation. See [library query/search](/Users/honey/Code/Multifeed/apps/web/src/components/posts/PostLibrary.tsx:95), [backend limit](/Users/honey/Code/Multifeed/apps/backend/convex/posts.ts:862), and [calendar result handling](/Users/honey/Code/Multifeed/apps/web/src/components/calendar/PostCalendar.tsx:87).

9. **P2: Paid feature descriptions exceed the implementation.** Inbox renders a heading and description. The schema defines inbox and metric tables, but the checked source has no ingestion job for inbox items and no writer for post metrics. Engagements therefore has no implemented provider synchronization path. Plans also advertise team approvals and bulk video scheduling without corresponding implemented workflows found in this audit. Implement these or clearly mark them unavailable before selling them as included functionality. See [Inbox](/Users/honey/Code/Multifeed/apps/web/src/app/(dashboard)/inbox/page.tsx:8), [plan features](/Users/honey/Code/Multifeed/packages/plans/src/index.ts:80), and [cron jobs](/Users/honey/Code/Multifeed/apps/backend/convex/crons.ts:1).

10. **P2: LinkedIn resume can publish only part of an image carousel.** Each uploaded image gets checkpointed immediately. If the action is interrupted after the first image, the resumed run finds nonempty `mediaIds` and skips the entire upload loop. It then creates the post with only the checkpointed images. Store completion per source asset and upload any missing assets before creating the post. See [resume and upload loop](/Users/honey/Code/Multifeed/apps/backend/convex/publishing/linkedin.ts:247). This is a code-traced interruption scenario, not a live provider reproduction.

11. **P2: Upload size checks happen after storage has accepted the bytes.** Upload URL generation only checks authentication. The installed R2 helper signs a PUT without a content-length constraint. The 100 MB check in `confirmMediaUpload` rejects registration after the object is uploaded, and no cleanup path was found for oversized or abandoned objects. An authenticated caller can bypass the browser file-size check and consume storage without finalizing. Enforce upload resource limits at an appropriate trusted boundary and clean up abandoned objects. See [upload authorization](/Users/honey/Code/Multifeed/apps/backend/convex/media/r2.ts:20) and [post-upload check](/Users/honey/Code/Multifeed/apps/backend/convex/media/r2.ts:103).

12. **P2: Concurrent invitations can exceed the plan's seat limit.** The endpoint reads members and invitations, checks remaining seats, then calls the external invitation service. Two requests for the last seat can both pass that read. Use an atomic reservation or an identity-provider-enforced limit, with failure reconciliation. See [seat check and invite](/Users/honey/Code/Multifeed/apps/web/src/app/api/team-members/route.ts:76). The race was not exercised because doing so would email invitations.

13. **P2: Dependency findings need cleanup and reachability review.** `pnpm audit --prod` reported 15 advisories. A large group enters through `shadcn`, which is listed in production dependencies even though it is a development CLI. Other findings enter through Next/PostCSS and Hexclave. Separate the CLI from runtime dependencies, update compatible affected packages, and review the actual use of the flagged APIs. Moving a dependency does not itself fix its vulnerabilities. The machine-readable registry result is saved in [audit-dependencies.json](/Users/honey/Code/Multifeed/audit-dependencies.json). Do not interpret registry severity as confirmed exploitability in this application.

**Further weaknesses and unresolved product decisions**

- The global `billing:webhooks` write guard makes webhook processing for unrelated teams contend on one document. Current insights show no observed contention; this is a scaling concern, not a reason to redesign billing immediately. Prefer subscription- or team-scoped serialization if measurements justify it. See [guard](/Users/honey/Code/Multifeed/apps/backend/convex/billing.ts:292).
- Publishing resumes are prioritized behind the first 100 newly due posts, and the returned `hasMore` does not schedule a continuation. A sustained backlog can delay recovery. Checkpoint persistence also catches and logs errors before allowing publishing to continue. Provider timeouts and 429 responses generally become failed targets rather than receiving bounded automatic retry with backoff. See [dispatch order](/Users/honey/Code/Multifeed/apps/backend/convex/publishing.ts:118) and [checkpoint callback](/Users/honey/Code/Multifeed/apps/backend/convex/publishing/actions.ts:312).
- Calendar enrichment can read 500 posts and 50,000 targets at the supported per-post maximum, exceeding the 32,000-document transaction budget before returning its truncation warning. Bound the aggregate work, not just each individual collection. This is a worst-case calculation, not an observed workload. See [calendar query](/Users/honey/Code/Multifeed/apps/backend/convex/posts.ts:942) and [Convex transaction limits](https://docs.convex.dev/production/state/limits#transactions).
- Subscription downgrade/expiry changes the limits used for new connections, but existing active accounts remain publishable and reconnects bypass net-new connection limits. Decide whether this is intended grandfathering. If paid limits must constrain continuing use, enforce that policy in the backend publishing path. See [connection accounting](/Users/honey/Code/Multifeed/apps/backend/convex/oauth/accounts.ts:229) and [publishing account check](/Users/honey/Code/Multifeed/apps/backend/convex/publishing/actions.ts:224).
- The calendar's previous/next icon buttons lack accessible names, the billing switch lacks a label, and accessibility lint rules are disabled. Account selection buttons also lack an exposed pressed state. See [calendar controls](/Users/honey/Code/Multifeed/apps/web/src/components/calendar/PostCalendar.tsx:222), [billing switch](/Users/honey/Code/Multifeed/apps/web/src/components/billing/BillingPage.tsx:199), and [lint configuration](/Users/honey/Code/Multifeed/apps/web/biome.json:32).
- The upload preview reads complete files into base64 data URLs, including up to ten 100 MB images before serial upload. Use object URLs and release them when no longer needed to avoid unnecessary memory growth. See [preview preparation](/Users/honey/Code/Multifeed/apps/web/src/components/posts/PostMediaUploader.tsx:244).
- No checked-in CI workflow, application error-reporting integration, or operational instructions for billing reconciliation, token-key rotation, orphan-media cleanup, and ambiguous provider delivery were found. Hosted settings may exist outside the repository; they were not audited.

**What is worth preserving**

The OAuth flow binds state to both team and user, consumes it atomically, and protects the exchange with a server secret. Access and refresh tokens use AES-GCM and are omitted from public account responses. Post, account, and media operations check team ownership. Webhooks verify the raw body before interpretation and deduplicate event IDs. Queries use indexes and explicit result bounds, cleanup uses follow-up batches, and list enrichment avoids repeated account fetches. These are concrete strengths and explain why the architecture and type-safety scores are substantially higher than publishing reliability.

The query review used the [official Convex best practices](https://docs.convex.dev/understanding/best-practices/) as a reference for indexes, bounded results, and public function validation.

**Recommended order of work**

1. Repair Post now, billing permissions, checkout duplication, and the cron scheduling budget.
2. Fix saved-media removal, repeated draft saves, and LinkedIn checkpoint completion.
3. Map billing products to entitlements, make seat allocation safe under concurrency, and decide the downgrade policy.
4. Add library pagination, disclose calendar truncation, and align paid feature copy with delivered behavior.
5. Resolve dependency advisories, enforce upload resource limits, and add CI/operational safeguards. If tests are authorized in a follow-up, prioritize publishing state transitions, tenant/role checks, and billing concurrency over more helper-only tests.

The path to an 8/10 score is mainly correcting business behavior and proving the critical flows. A framework rewrite is not warranted by this audit.
